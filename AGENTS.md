## 1. Что это за проект

**Motherload** — складской терминал для анализа и мониторинга запасов комплектующих компьютерной техники. Внутренняя система для вымышленной белорусской компании: приёмка, расход по FIFO, перемещения, инвентаризация, ABC/XYZ, точка заказа, алерты, KPI, отчёты, аудит.

- Дисциплина: «Проектирование и разработка web-приложений».
- Интерфейс: русский. Код, имена, комментарии, коммиты: английский.
- Валюта: BYN, знак из официального шрифта НБРБ.
- Демо-данные: вымышленные, белорусские. Никаких реальных персональных данных.

### Стек (менять нельзя без согласования)

| Слой | Технология |
|---|---|
| Runtime | Node.js 24 LTS |
| Сервер | Express 5 |
| Шаблоны | EJS 3, SSR |

## 2. Жёсткие правила

1. **Только чистый JavaScript.** Никакого TypeScript, `.ts`, `ts-node`, декораторов. JSDoc разрешён и приветствуется для публичных функций.
2. **ES-модули.** `"type": "module"`, `import`/`export`, никакого `require`, `module.exports`, `__dirname` без `fileURLToPath`.
3. **SSR-first.** Страница — это HTML, отрендеренный на сервере. Клиентский JS только для прогрессивного улучшения: динамические строки форм, графики, FIFO-предпросмотр, тосты.
4. **Одна каскадная таблица стилей** — `public/css/app.css`. Никаких вторых CSS-файлов, `<style>`, `style="..."`, Tailwind, Bootstrap, CSS-модулей.
5. **Никаких inline-скриптов** — CSP это запрещает. Только `<script type="module" src="...">`.
6. **Никакого SQL в контроллерах и EJS.** Только слой `repositories/`.
7. **Никакой бизнес-логики в EJS.** Шаблон только отображает подготовленные данные.
8. **Все деньги — через `decimal.js`.** `Number` для цен и себестоимостей запрещён. Из PostgreSQL `numeric` приходит строкой — не приводить к float.
9. **Все мутации остатков — в транзакции** с блокировкой партий `FOR UPDATE`.
10. **Никаких секретов в репозитории.** `.env` игнорируется, `.env.example` содержит только заглушки.
11. **Никаких `console.log`.** Только `req.log` / `logger` (Pino). В тестах допустим вывод `node:test`.
12. **Не хардкодить пути и данные своей машины.** Только `DATABASE_URL`, `PORT` и т.п. из окружения. Демо-данные — в `db/seed/data.js`.
13. **Не редактировать уже применённые миграции.** Только новая миграция.
14. **Один этап — один коммит.** Не смешивать несвязанные изменения.
15. **Не удалять чужой код без понимания.** Сначала выяснить, зачем он. Удаление — функциональное изменение.
16. **Комплектующие меняет только admin** через `/admin/components`; SKU неизменяем; позиция с историей архивируется, а не удаляется.
17. **Документы создаются сразу проведёнными.** Черновиков складских документов нет; редактирование проведённого запрещено; номер генерируется из `document_sequences`.
18. **Инвентаризация замораживает склад** с `draft` до `approved`/`cancelled`; любые складские операции с этим складом — 409.

## 4. Архитектура и код

### Слои

```
routes → middleware → controller → service → repository → PostgreSQL
                                   ↓
                                 view (EJS)
```

- `controller` — разбор HTTP, Zod-валидация, вызов сервиса, redirect/render. Никакого SQL.
- `service` — бизнес-правило, транзакция, вызов чистых доменных функций.
- `repository` — SQL и маппинг. Никаких HTTP-объектов.
- `domain` — чистые функции без БД и Express: `fifo`, `abc`, `xyz`, `reorder`, `kpi`, `csv`, `money`.
- `view` — только данные из контроллера.

### Структура

```
src/app.js, src/server.js
src/config/{env,inventory}.js
src/db/{pool,migrate,seed}.js
src/middleware/*
src/domain/*
src/repositories/*
src/services/*
src/controllers/*
src/routes/{web,api}.js
src/views/{layouts,partials,pages}/*.ejs
db/migrations/*.sql
db/seed/data.js
public/{css,js,fonts,img}
test/{unit,integration}
scripts/*
```

### Стиль кода

- 2 пробела, точки с запятой, одинарные кавычки, trailing comma — как настроит Prettier.
- Именованные экспорты. Default export только если библиотека требует.
- `camelCase` для переменных/функций, `PascalCase` для классов, `SCREAMING_SNAKE_CASE` для констант.
- Файлы: `kebab-case.js`; EJS: `kebab-case.ejs`.
- Функции маленькие, с одной ответственностью. Ранний возврат вместо вложенных `if`.
- Никаких «умных» однострочников, которые нельзя прочитать без контекста.
- Комментарии — только «почему», не «что». JSDoc для публичных функций сервисов/домена.
- TODO/FIXME/HACK — с причиной и этапом. Не оставлять «на потом» без записи в `IMPROVEMENTS.md`.

### Ошибки

- Доменные классы: `ValidationError`, `InsufficientStockError`, `ForbiddenError`, `NotFoundError`, `ConflictError`.
- Централизованный error middleware: известные → 400/403/404/409, неизвестные → 500 + лог с `requestId`.
- В UI — человеческий русский текст. В логах — английский, структурный.
- Не глотать ошибки. `catch` без действия запрещён.

### Валидация

- Zod-схемы в `src/validation/` или рядом с контроллером.
- Проверять на границе: body, params, query. Не доверять клиенту, даже если JS уже проверил.
- Ошибки возвращать в форму с сохранением введённых значений.

### Деньги и даты

- `decimal.js` для любых вычислений. На входе — строки, на выходе — `toFixed(2)`/`toFixed(4)`.
- В БД: `numeric(14,4)` для себестоимости, `numeric(12,2)` для цен.
- Даты документов — `date`; события — `timestamptz`.
- Форматирование только через хелперы `formatMoney`, `formatDate`, `formatDateTime`, `formatQty`.

## 5. База данных

- Миграции: `db/migrations/NNN_description.sql`, только вперёд. Применённые не редактировать.
- Имена таблиц и колонок — `snake_case`, множественное число таблиц.
- PK — `GENERATED ALWAYS AS IDENTITY`.
- FK — всегда, с осознанным `ON DELETE`. По умолчанию `RESTRICT`.
- `CHECK` на количества, цены, статусы.
- `timestamptz NOT NULL DEFAULT now()` для аудита.
- Индексы под фактические запросы: остатки, движения, партии, алерты, аудит.
- Остаток не хранится отдельным полем. Источник — `stock_movements` (ledger) и `stock_batches` (FIFO/стоимость).
- Сиды идемпотентны: повторный запуск не дублирует данные. Пароли хешируются Argon2id.
- Тестовая БД отдельная: `TEST_DATABASE_URL`. Перед тестами `TRUNCATE ... RESTART IDENTITY CASCADE`.

### Транзакции

```js
await withTransaction(async (client) => { ... });
```

- Приёмка: документ + строки + партии + движения.
- Расход/перемещение: документ + строки + `FOR UPDATE` партий + `batch_consumptions` + движения.
- Перед любой складской операцией проверить, что на складе нет инвентаризации в `draft`/`submitted`; иначе 409.
- Номер документа выдаётся в той же транзакции через `document_sequences` (`INSERT ... ON CONFLICT DO UPDATE ... RETURNING`), без `MAX(id)`.
- Инвентаризация: утверждение целиком или откат; перед утверждением сверить текущий остаток с `expected_qty`.
- Никаких частично проведённых документов.

## 6. Безопасность

- Argon2id; параметры по умолчанию библиотеки, хеш в `users.password_hash`.
- Пароль: ≥10 символов, строчная, заглавная, цифра. Сообщение — по-русски.
- Сессия: `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, TTL 8 ч, rolling, regenerate при входе.
- CSRF: double-submit на всех POST/PUT/PATCH/DELETE. В HTML — hidden `_csrf`, в fetch — `X-CSRF-Token`.
- Helmet + строгий CSP без `unsafe-inline`.
- Rate limit: `/login` 5/мин на IP; глобально 300/мин.
- RBAC middleware на каждом защищённом роуте. Проверять роль на сервере, не в шаблоне.
- SQL только параметризованный.
- EJS экранирует `<?= ?>`. `<?- ?>` использовать только для доверенного HTML (иконки, пагинация), никогда для пользовательских данных.
- Аудит каждой мутации: `action`, `entity_type`, `entity_id`, `details` без секретов.
- HTTPS: `HTTPS=1` + `TLS_CERT_PATH`/`TLS_KEY_PATH`; HSTS при secure.
- Бэкапы: `scripts/backup.js` (pg_dump), `scripts/restore.js`; ретенция 7 дней. Веб-доступа к дампам нет.
- Не логировать пароли, хеши, CSRF-токены, содержимое cookie.

- Никакой цвет как единственный признак.

### Адаптив

### Микрокопирайт

- Человеческий русский, без канцелярита.
- Кнопки называют результат: «Провести приёмку», «Утвердить инвентаризацию».
- Ошибки конкретные: что случилось, что делать.
- Не «Invalid input», не «Error 400», не «Entity not found».

### SEO

- Публичный `/` индексируется: `title`, `description`, `canonical`, OG, Twitter, JSON-LD `SoftwareApplication`.
- Приватные страницы — `<meta name="robots" content="noindex, nofollow">`.
- `robots.txt` и `sitemap.xml` отдаются приложением.
- Семантические теги, один `h1`, `alt` у изображений.
- OG-обложка `public/img/og-cover.png` 1200×630.
- Никакого скрытого SEO-текста.

## 8. Тесты и проверка

### Правила

- Фреймворк — `node:test`. Новые фреймворки не добавлять.
- Unit — чистые функции (`fifo`, `abc`, `xyz`, `reorder`, `csv`, `money`).
- Integration — Supertest + реальный PostgreSQL, отдельная БД.
- Тест пишется на то, что может сломаться тихо: FIFO, деньги, права, транзакции, границы.
- Не тестировать переименования, константы, тонкие обёртки. Если тест не нужен — сказать в отчёте.
- Багфикс в нетривиальном коде — обязательный регрессионный тест (падал до, проходит после).
- Тесты не зависят от порядка запуска; каждый чистит своё.
- Никаких `sleep`, кроме явного ожидания внешнего процесса.

### Команды

```bash
npm run lint
npm run format:check
npm test
npm run test:unit
npm run test:integration
npm run smoke        # нужен запущенный сервер и Chrome
```

## 9. Git и рабочий процесс

- Коммит — на каждый завершённый этап. Формат: `type: brief description` (`feat`, `fix`, `refactor`, `chore`, `docs`, `style`, `perf`, `test`, `ci`, `build`, `a11y`).
- Сообщение и тело — на английском, тело отвечает «почему».
- Перед рискованным исправлением — промежуточный коммит, чтобы можно было откатиться.
- Не коммитить `.env`, `node_modules`, `backups`, `coverage`, `tmp`.
- Не делать `git push`, `git reset --hard`, `git rebase` без явного указания.
- Не менять чужие файлы вне рамок этапа.

## 12. Подводные камни

- `pg` возвращает `numeric` строкой. Не делать `Number()` для денег; передавать в `Decimal`.
- `date` из `pg` приходит как JS `Date` в локальной зоне. Для документов форматировать без сдвига (использовать `date`-строку или `pg-types`).
- EJS-шаблоны не имеют доступа к `req`, если не пробросить. Использовать `res.locals`.
- CSP ломает inline `<script>` и `onclick`. Только внешние модули и `addEventListener`.
- Chart.js подключать как локальный ESM-билд, не с CDN (офлайн-воспроизводимость).
- CSV для Excel: BOM `\uFEFF`, разделитель `;`, иначе русская локаль ломает колонки.
- Партии сортировать по `(received_at, id)`, иначе FIFO нестабилен.
- При перемещении нельзя терять `unit_cost`; создавать партии на приёмнике с теми же ценами.
- Инвентаризация: пустое поле факта ≠ 0. Не подставлять 0 по умолчанию.
- Нельзя утверждать инвентаризацию повторно.
- Сессия в БД: таблица создаётся миграцией, не автоматически.
- Docker: приложение ждёт healthy БД, а не просто старт контейнера.
- Windows: пути и `pg_dump` в `PATH`; инструкция должна это учитывать.
- `min_stock`/`max_stock` — на каждый склад; не сравнивать суммарный остаток с одним порогом.
- Инвентаризация: отправка требует заполненный факт во всех строках; пустое поле ≠ 0; есть массовое «Заполнить по учёту».
- Аналитика не должна зависеть от реальной даты запуска: `ANALYTICS_REFERENCE_DATE` обязателен в демо и тестах.
- Номера документов не вводить вручную и не считать через `MAX(id)`.
- Позицию с партиями/движениями нельзя удалять — только архивировать.
